# Project structure and run contract

Keep one canonical implementation path, one source-of-truth folder for supplied inputs, and one generated-results location. Root-level compatibility shims remain only to avoid breaking earlier imports and commands.

    Aircraft-Crew-Recovery/
    ├── README.md
    ├── requirements.txt
    ├── setup_workspace.py             compatibility launcher
    ├── MGT.py / pairings_builder.py   compatibility shims to originals/
    ├── project_paths.py               compatibility shim to src/
    ├── column_generation.py            finite-pool LP research entry point
    ├── originals/                     canonical supplied source files; immutable
    ├── input/                          prepared schedule and pairing report
    ├── src/crew_recovery/              reusable recovery, MGT, costing, aircraft and validation code
    ├── scripts/                        canonical runners, preparation and audit commands
    ├── tests/                          regression and small-instance tests
    ├── docs/                           project map, objective contract and handoff notes
    ├── output/                         historical experiments plus ignored current run output
    ├── logs/                           historical solver logs
    └── patches/                        archived snapshots; not active modules

## Canonical run

Run from the repository root using Python 3.11:

    python -m pip install -r requirements.txt
    python setup_workspace.py
    python -m pytest -q tests
    python scripts/run_joint_recovery_horizons.py --time-limit-seconds 180

This prepares the canonical runtime inputs, runs the test suite, then writes the current run to output/joint_recovery/{1W,1M,154D}/ and output/joint_recovery/horizon_summary.json.

## Input ownership

- originals/ is the only source of truth for supplied schedule, pairing report, MGT, FDP, cost, revenue, and AIRFLITE line-of-work inputs.
- input/ is generated by setup_workspace.py. Do not edit it as a substitute for changing a source file in originals/.
- Exact duplicate schedule rows are audited during preparation.
- Redundant root-level copies of supplied workbooks and CSV data have been removed. This prevents a script from accidentally selecting an outdated duplicate.
- Do not edit the supplied files under originals/ during routine runs.

## Output ownership

The successful CI workflow uploads the current recovery results as a recovered-schedules artifact. Locally generated output/joint_recovery/ and output/joint_recovery_expanded/ folders are ignored by Git to prevent run products from becoming mixed with the committed historical experiments.

Previously committed files in output/ are historical experiment/baseline evidence, not the latest recovery snapshot unless a document names a specific run and commit. logs/ also contains historical evidence. patches/ stores archived snapshots; it is not the active implementation.

Each current horizon output contains a JSON summary, flight-level operate/cancel decisions, selected pairings, aircraft rotations, validation evidence and a workbook. The aggregate horizon_summary.json is the compact comparison across the three horizons.

## Interpret the statuses

- PROTOTYPE_OPTIMAL_WITH_PROVISIONAL_TAILS: the small MILP is optimal only for the restricted supplied pairing and generated route domain; provisional line resources prevent operational acceptance.
- HEURISTIC_FEASIBLE_NOT_OPTIMAL: the large-horizon heuristic has produced a feasible plan under current candidate/resource assumptions; no global optimum is claimed.
- PARTIAL_RECOVERY_UNRESOLVED_MGT: a plan exists for resolvable-MGT flights, while unresolved flights remain separately reported.
- CANCEL: not selected in the restricted plan. It is not a certificate that a flight is impossible to operate.
- UNRESOLVED_MGT: a missing/conflicting/effective-date data blocker, not a cancellation.

## Do not broaden the handoff

Retiming, flight-copy selection, verified tail registrations, an airline-approved equipment compatibility crosswalk, full operating costs, and the full crew roster/set objective remain unintegrated. The prototype handoff is complete when the standard run is reproducible, tests and independent checks pass, results are documented, and these limitations are explicit. Do not add new heuristics unless a concrete reproducible defect is found or authoritative missing input changes the model.


## Current-run cleanup contract

- The only default output location for the canonical horizon run is `output/joint_recovery/`.
- `scripts/run_joint_recovery_horizons.py` replaces this dedicated output directory at startup, then writes each requested horizon and one aggregate `horizon_summary.json`.
- `scripts/run_disruption_recovery.py` similarly replaces its selected dedicated `--output-dir` before generating trials and selected results.
- Output cleanup refuses the repository root, the shared `output/` parent, and paths outside `output/`. It does not touch `originals/`, `input/`, code, tests, docs, logs, or historical experiment files elsewhere under `output/`.
- Old committed files elsewhere under `output/`, `logs/`, and `patches/` remain historical evidence; they are not the latest run. They were not deleted by this cleanup change. Do not add new historical output files to Git.
- To run just one horizon, pass e.g. `--horizons 1W`; that still replaces the canonical output directory, by design. The aggregate summary then describes only the requested horizons.
